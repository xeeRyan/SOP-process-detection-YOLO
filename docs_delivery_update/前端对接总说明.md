# SOPAID 前端对接总说明

文档版本：2026-07-31  
适用交付包：`SOPAID_Deliever11`

本文是前端工程师的总入口，内容以本次交付目录和实际源码为准。

## 1. 接入方式选型

| 需求 | 接口 | 输入 | 输出 | 包含 SOP 业务 |
|---|---|---|---|---|
| 项目、ROI、流程、抽帧、标注、数据集、训练、整段视频分析 | Python TCP | 视频文件路径、JSON | SOP 结果、步骤、事件、结果视频/JSON | 是 |
| WPF 实时摄像头逐帧检测 | C++/CLR SDK | 每帧 `byte[]` | 本帧检测框或手部 21 点 | 否 |
| 已有图片逐张检测 | C++/CLR SDK | 解码后的像素数组 | 本图检测结果 | 否 |
| C# 直接向 C++ SDK 传视频路径 | 当前 CLR 包装层不支持 | - | - | - |

关键边界：

- Python `detect.video_path` 是视频文件路径，不是摄像头编号。
- CLR 的 `Evaluate` 接收单帧像素。摄像头由前端打开，再把每帧转换为支持的格式。
- 原生 C++ 源码有视频路径接口，但本次 `SOPAID_wrapper.dll` 未暴露该方法。
- C++/CLR 只做 YOLO 与手部模型推理，不负责 ROI、跟踪、事件、步骤顺序、超时或 SOP 状态机。

## 3. 环境和依赖

### 3.1 共同要求

- Windows 10/11 x64，应用进程必须为 x64。
- 路径优先使用绝对路径；路径由执行算法的机器解释。
- 模型、DLL、视频可读，输出目录可写。

### 3.2 Python TCP

- Python 已封装，前端无需安装 Python 或 pip 包。
- 默认连接 `127.0.0.1:9000`。
- 启动时必须把工作目录设为 `SOP_PYD.exe` 所在目录。
- 服务端 `listen(1)` 串行处理；每个连接只发送一个请求，响应后服务端关闭连接。
- 请求为 UTF-8 JSON；服务端单次 `recv(102400)`，前端请求应小于 100 KB。

### 3.3 C++/CLR

- 目标为 .NET Framework 4.7.2、x64。
- 引用 `C++推理SDK\frontend_bin\SOPAID_wrapper.dll`。
- 把 `frontend_bin` 全部文件复制到前端 EXE 输出目录。
- 安装 `vc_redist.x64.exe`；工程使用 MSVC v142，OpenCV 为 `opencv_world4130.dll`。
- 当前 `SOPAID.dll` 加载依赖包内 ONNX Runtime、TensorRT、LibTorch 运行库，推荐完整部署。
- GPU 模式要求兼容的 NVIDIA 驱动；TensorRT engine 不保证跨 GPU/驱动/运行时通用。

## 5. 实现原则与限制

- Python 长任务异步等待；前端超时/取消不会中止后端任务。
- TCP 响应读取到连接关闭，不能用 `DataAvailable == false` 判断结束。
- CLR evaluator 初始化一次并复用，不要逐帧加载模型。
- CLR 返回 `false` 时读取 `LastError.Status/Message`。
- SDK 支持 Gray、BGR、BGRA；RGB/RGBA 要先转换。
- 类别 ID 与 `project.json.classes[].id` 或 `ClassNamesCsv` 顺序一致。
- Python 无任务 ID、进度、查询、取消、逐帧推送。
- CLR 不打开摄像头、不读取视频路径、不编码结果视频、不运行 SOP 状态机。
- evaluator 没有线程安全承诺，同一实例应串行调用。

## 6. 最小验收

- Python：运行根目录 `运行Python健康检查.cmd`。
- Python Demo：运行 `启动Python_WPF测试Demo.cmd`，完成 health、项目读取和短视频 detect。
- CLR：在 `C++推理SDK\frontend_bin` 运行 `运行CLR冒烟测试.cmd`。
- 正式包在一台未安装开发工具的 Windows x64 机器做冷启动验收。
